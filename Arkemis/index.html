Analisi Comparativa Piattaforme Git

GitHub Cloud vs GitLab Self-hosted vs Gitea

Ricerca aggiornata al: 10 Ottobre 2025

Sintesi Rapida

  • GitHub Cloud (SaaS su Microsoft Azure) adotta fatturazione usage-based con oltre 1.000 integrazioni nel Marketplace, ideale per team distribuiti che sfruttano l’ecosistema.
  • GitLab Self-Hosted privilegia controllo totale, personalizzazione e conformità enterprise, ma richiede team DevOps dedicati e reference architecture da seguire.
  • Gitea è software gratuito (MIT) da installare su VPS (~$40/mese): rapido per team piccoli, ma con feature enterprise spesso assenti o da integrare via plugin.
  • CI/CD: GitHub Actions offre un marketplace vasto ma necessita di governance (allow-list, policy, approvazioni); GitLab CI include nativamente approvazioni, artifact retention, SBOM; Gitea si appoggia a Gitea Actions/Act Runner, non equivalenti al 100% a GitHub Actions.
  • Costi stimati (assunzioni 2025): GitHub Enterprise Cloud ≈ $21/utente/mese ($252/anno), GitLab Premium ≈ $29/utente/mese ($348/anno) + infrastruttura, Gitea richiede solo hosting.
  • Tempi di setup (stime indicative): GitHub Cloud quasi immediato, GitLab self-hosted 2–4 settimane, Gitea 1–2 giorni a seconda di SSO, runner, backup e compliance.

Introduzione & Scenari

La scelta della piattaforma di gestione del codice sorgente e del ciclo DevOps incide direttamente su produttività, sicurezza e capacità di scalare. GitHub Cloud (SaaS), GitLab Self-Hosted e Gitea (self-hosted) rappresentano tre modelli distinti, ognuno con implicazioni tecniche, economiche e organizzative differenti.

Questo report, aggiornato al 10 ottobre 2025, si basa esclusivamente su fonti primarie e confronta le tre soluzioni su criteri verificabili. L'obiettivo è supportare decisioni informate in tre scenari: team piccolo (5–20 sviluppatori), team in crescita (20–150 sviluppatori in 24 mesi) e azienda strutturata (500+ utenti con requisiti enterprise).

Sulle sezioni successive trovi approfondimenti tematici, il framework decisionale e una scorecard ponderata convertibile in canvas visivi e documentazione formale.

Team Piccolo (5–20 sviluppatori)

Priorità: costi contenuti, setup rapido, gestione semplice.

🏆 Raccomandazione: Gitea Self-Hosted

Software open-source leggero con licenza MIT. Richiede una VPS economica (~$40/mese) e offre funzionalità essenziali, pur mancando di certificazioni enterprise.

Setup stimato: 1–2 giorni (dipende da SSO, backup, runner).

💡 Nota operativa

Se serve SaaS immediato con minimo sforzo operativo, GitHub Cloud (Free/Team) resta l'alternativa più rapida da abilitare.

Team in Crescita (20–150 sviluppatori in 24 mesi)

Priorità: scalabilità controllata, compliance progressiva, automazione CI/CD.

🏆 Raccomandazione: GitLab Self-Hosted su AWS

Licenza Premium ≈ $29/utente/mese (Ultimate ≈ $99). Reference architecture scalabile, runner Kubernetes/Docker Machine, policy di compliance avanzate.

Setup stimato: 2–4 settimane (infrastruttura, SSO, backup, DR).

💡 Nota operativa

Valuta GitHub Cloud Enterprise se il team non può sostenere la gestione dell'infrastruttura e privilegia una soluzione completamente gestita.

Azienda Strutturata (500+ utenti)

Priorità: requisiti enterprise, compliance rigorosa, supporto globale.

🏆 Raccomandazione: GitHub Cloud Enterprise

SaaS gestito da Microsoft Azure con SLA globali, funzioni avanzate di sicurezza (SSO, SCIM, secret scanning) e certificazioni SOC 2 Type II / ISO 27001. Licenza ≈ $21/utente/mese.

Setup stimato: ore/giorni (configurazione policy, integrazione SSO, governance Actions).

💡 Nota operativa

Prendi in considerazione GitLab Dedicated o GitHub Enterprise Server se policy interne impongono residenza dei dati on-prem o isolamento di rete totale.

Possibile approccio ibrido: GitHub Cloud con runner self-hosted in VPC privati, o GitLab Self-Managed con mirror verso GitHub Cloud per collaborazione open-source.

GitHub Cloud

  • Licenza: ~$21/utente/mese (GitHub Enterprise Cloud ≈ $252/anno).
  • CI/CD: minuti di esecuzione inclusi variabili per piano con fatturazione usage-based (OS/dimensione runner).
  • Storage LFS, artifact e traffico privato: tariffazione a consumo.
  • TCO: riduce l’Opex interno (SaaS gestito) ma comporta minor controllo sulla residenza dei dati.

GitLab Self-Hosted su AWS

  • Licenza: ~$29/utente/mese (Premium ≈ $348/anno; Ultimate ≈ $1.188/anno).
  • Infrastruttura: EC2 (es. m6i.2xlarge), storage EBS, backup S3/Glacier, monitoring (CloudWatch/Prometheus).
  • CI/CD: runner autoscalati (spot/on-demand), artifact e registry da dimensionare.
  • TCO: medio-alto con costi Capex/Opex separati; richiede personale DevOps/SRE dedicato.

Gitea Self-Hosted

  • Licenza: $0 (MIT) o ~$114/anno per Gitea Enterprise (supporto).
  • Infrastruttura: VPS/VM (~$40/mese) + costi di storage, backup, monitoring e runner separati.
  • TCO: basso su piccola scala ma cresce con l’effort manuale richiesto oltre ~500 utenti.

Il TCO effettivo dipende dal volume CI/CD (minuti, artifact, LFS, egress), dai requisiti di disponibilità e dalla maturità operativa del team.

Framework Decisionale Interattivo

Usa questi strumenti per trovare la soluzione più adatta alle tue esigenze specifiche.

1. Domande chiave prima di scegliere

  • Qual è la dimensione attuale del team e la previsione di crescita nei prossimi 24 mesi?
  • Quali requisiti di sicurezza e compliance devono essere soddisfatti (es. ISO 27001, SOC 2, GDPR)?
  • Serve una soluzione SaaS completamente gestita o è necessario il controllo completo via self-hosting?
  • Qual è il budget disponibile e come bilanciare Opex vs Capex infrastrutturale?
  • Quali integrazioni con altri strumenti (IDE, package registry, vulnerability DB) sono imprescindibili?
  • Esistono vincoli sulla residenza dei dati in specifiche regioni (es. UE)?
  • Quale livello di supporto e manutenzione interna può essere garantito nel tempo?

Conclusione

La scelta tra GitHub Cloud, GitLab Self-Hosted e Gitea dipende da un mix di requisiti tecnici, economici e organizzativi. GitHub Cloud risponde meglio alle esigenze di aziende strutturate con team distribuiti, bisogno di SLA globali e funzioni di sicurezza avanzate. GitLab Self-Hosted è ideale quando servono controllo completo, personalizzazione e isolamento dei dati su AWS o on-premise. Gitea resta l'opzione più agile e conveniente per team piccoli che vogliono autonomia e costi contenuti.

Il framework decisionale e la scorecard ponderata convertono l'analisi qualitativa in criteri misurabili: allinea i pesi ai tuoi vincoli per ottenere un punteggio immediato e oggettivo. Usa queste sezioni come canvas dinamico per guidare stakeholder tecnici e business verso una decisione condivisa e motivata.

Glossario Essenziale

SSO (Single Sign-On)
Permette agli utenti di autenticarsi una sola volta per accedere a più servizi.
SCIM (System for Cross-domain Identity Management)
Protocollo per automatizzare il provisioning (creazione, modifica, eliminazione) degli utenti tra sistemi diversi.
RPO/RTO (Recovery Point/Time Objective)
RPO: massima perdita di dati accettabile. RTO: tempo massimo per ripristinare un servizio dopo un disastro.
SBOM (Software Bill of Materials)
Una lista formale e leggibile da una macchina di tutti i componenti, librerie e dipendenze di un software.
BYOK (Bring Your Own Key)
Modello in cui il cliente gestisce le proprie chiavi di cifratura tramite un KMS esterno, mantenendo il controllo sui dati crittografati.
