Cos'è un LLM

Large Language Model

Un LLM è un modello di intelligenza artificiale addestrato su enormi quantità di testo per comprendere e generare linguaggio naturale.

Caratteristiche principali

  • Miliardi di parametri (pesi neurali)
  • Addestramento su terabyte di testo
  • Architettura Transformer
  • Capacità di generazione autogressiva

Esempi di LLM

  • GPT-4 — OpenAI
  • Claude — Anthropic
  • Gemini — Google
  • Llama — Meta (open source)

Fonte: Vaswani et al., "Attention Is All You Need", 2017

Come funziona un LLM

Il modello predice il token successivo basandosi sul contesto precedente. Ogni token può essere una parola, parte di parola o simbolo.

Cos'è un client

Client API

Un client è un'applicazione o libreria che comunica con un server (in questo caso, un LLM) tramite API (Application Programming Interface).

Tipi di client

  • SDK ufficiali — OpenAI Python, Anthropic SDK
  • HTTP diretto — Chiamate REST API
  • Interfacce web — ChatGPT, Claude.ai
  • Framework — LangChain, LlamaIndex

Componenti di una richiesta

  • Endpoint — URL del servizio
  • API Key — Autenticazione
  • Payload — Messaggio e parametri
  • Headers — Metadati della richiesta

Il flusso tipico: richiesta → autenticazione → elaborazione → risposta in streaming o batch.

Temperatura

Cos'è la temperatura?

La temperatura controlla la casualità delle risposte. Valori bassi = output prevedibili, valori alti = output creativi.

Valore Comportamento Caso d'uso
0.0 Deterministico, sempre la stessa risposta Codice, dati strutturati
0.3 - 0.5 Bilanciato, leggera variazione Q&A, assistenza
0.7 - 1.0 Creativo, più variabilità Scrittura creativa
> 1.0 Molto casuale, può essere incoerente Sperimentazione

Parametri importanti (1/2)

Max Tokens

Limite massimo di token nella risposta.

Tipico: 256 - 4096

1 token ≈ 0.75 parole in italiano

Top-P (Nucleus Sampling)

Considera solo i token con probabilità cumulativa ≤ P.

Tipico: 0.9 - 1.0

Alternativa alla temperatura

Top-K

Considera solo i K token più probabili.

Tipico: 40 - 100

Limita il vocabolario di scelta

Frequency Penalty

Penalizza token già usati frequentemente.

Range: -2.0 a 2.0

Evita ripetizioni

Parametri importanti (2/2)

Presence Penalty

Penalizza token già apparsi (indipendentemente dalla frequenza).

Range: -2.0 a 2.0

Favorisce nuovi argomenti

Stop Sequences

Stringhe che fermano la generazione.

Esempio: ["\n\n", "END"]

Controllo preciso dell'output

System Prompt

Istruzioni iniziali per definire il comportamento del modello.

Definisce personalità e regole

Context Window

Quantità massima di token che il modello può "vedere".

Tipico: 8K - 200K tokens

Cos'è RAG

Retrieval-Augmented Generation

RAG è un pattern architetturale che combina la ricerca di informazioni da fonti esterne con la generazione di un LLM, permettendo risposte basate su dati specifici e aggiornati.

"RAG permette agli LLM di accedere a conoscenza oltre il loro training, riducendo le allucinazioni e fornendo risposte verificabili."

Fonte: Lewis et al., "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks", 2020

Perché usare RAG

📚

Dati aggiornati

Accesso a informazioni post-training senza riaddestramento del modello.

✅

Meno allucinazioni

Risposte basate su fonti verificabili, non solo conoscenza parametrica.

🔒

Dati proprietari

Integra documenti interni senza esporli nel training.

Confronto: Fine-tuning modifica i pesi del modello (costoso, rigido). RAG aggiunge contesto a runtime (economico, flessibile).

Step 1: chunking dei documenti

I documenti vengono divisi in chunk (frammenti) di dimensione gestibile.

Strategie di chunking

  • Fixed size — N caratteri/token con overlap
  • Sentence-based — Frasi complete
  • Semantic — Paragrafi/sezioni logiche
  • Recursive — Split gerarchico

Parametri tipici

  • Chunk size: 256-1024 token
  • Overlap: 10-20% del chunk
  • Metadata: Titolo, fonte, data

Trade-off: Chunk piccoli = retrieval preciso ma poco contesto. Chunk grandi = più contesto ma meno precisione.

Step 2: embedding

Cos'è un embedding?

Un embedding è una rappresentazione numerica densa (vettore) che cattura il significato semantico del testo. Testi simili hanno vettori vicini nello spazio.

Modelli di embedding

  • OpenAI — text-embedding-3
  • Cohere — embed-v3
  • Open Source — BGE, E5, SBERT

Dimensioni tipiche

I vettori hanno 256 - 3072 dimensioni.

Più dimensioni = più capacità espressiva.

Nota: Lo stesso modello di embedding deve essere usato per documenti e query.

Step 3: vector database

Gli embedding vengono salvati in un vector database ottimizzato per ricerche di similarità.

Database popolari

  • Pinecone — Managed, scalabile
  • Weaviate — Open source, ibrido
  • Qdrant — Open source, Rust
  • Chroma — Leggero, embedded
  • pgvector — Extension PostgreSQL

Metriche di similarità

  • Cosine — Angolo tra vettori
  • Euclidean — Distanza geometrica
  • Dot product — Prodotto scalare

Algoritmi: HNSW, IVF, LSH

Step 4: retrieval

A runtime, la query viene trasformata in embedding e usata per recuperare i chunk più rilevanti.

1

Query embedding

La domanda viene convertita in vettore con lo stesso modello usato per i documenti.

2

Similarity search

Il vector DB trova i top-K chunk più simili (tipicamente K = 3-10).

3

Reranking (opzionale)

Un modello di reranking riordina i risultati per maggiore precisione.

Step 5: generation

I chunk recuperati vengono inseriti nel prompt come contesto.

System: Usa SOLO il contesto seguente per rispondere.
Se non trovi la risposta, dì "Non ho informazioni sufficienti."

Contesto:
{chunk_1}
{chunk_2}
{chunk_3}

Domanda: {user_query}

Risposta:

Best practice: Istruire il modello a citare le fonti e ammettere quando non sa.

Tecniche RAG avanzate

Hybrid Search

Combina semantic search (embeddings) con keyword search (BM25).

Query Expansion

L'LLM riformula la query in multiple varianti per catturare più risultati.

HyDE

Genera un documento ipotetico ideale e usa il suo embedding per la ricerca.

Parent-Child Retrieval

Recupera chunk piccoli ma passa al modello il documento parent.

Cos'è un agente AI

AI Agent

Un agente è un sistema AI che può ragionare, pianificare e agire autonomamente per raggiungere un obiettivo, utilizzando strumenti esterni e iterando fino al completamento.

Differenza chiave: Un LLM risponde a una domanda. Un agente risolve un problema usando multiple azioni e strumenti.

Componenti di un agente

🧠

LLM (Cervello)

Il modello che ragiona, pianifica e decide quale azione eseguire.

🔧

Tools

Strumenti esterni: API, database, browser, calculator.

💾

Memory

Contesto della conversazione e memoria a lungo termine.

Input
→
Reason
→
Act
→
Observe
→
Repeat

Tool use (function calling)

L'LLM può invocare funzioni esterne, ricevere i risultati e continuare il ragionamento.

Come funziona

  • Definisci tools con schema JSON
  • L'LLM decide se/quando usarli
  • Genera una "function call"
  • Il sistema esegue la funzione
  • Il risultato torna all'LLM

Esempi di tools

  • web_search — Cerca su internet
  • calculator — Calcoli matematici
  • send_email — Invia email
  • query_database — Query SQL
  • create_file — Genera file

Il pattern ReAct

Reasoning + Acting

ReAct alterna fasi di ragionamento (Thought) e azione (Action), permettendo all'agente di "pensare ad alta voce".

T

Thought

"Devo trovare il prezzo corrente delle azioni Apple. Userò web_search."

A

Action

web_search("Apple stock price today")

O

Observation

Risultato: "AAPL: $178.50 (+1.2%)"

Fonte: Yao et al., "ReAct: Synergizing Reasoning and Acting in Language Models", 2022

Cos'è la RAG agentica

Agentic RAG

RAG Agentica combina il retrieval di RAG con le capacità decisionali degli agenti. L'LLM non si limita a recuperare e rispondere, ma ragiona su cosa cercare, valuta i risultati e itera autonomamente.

"La RAG tradizionale è un one-shot. La RAG agentica è un processo iterativo e adattivo."

RAG tradizionale vs RAG agentica

Aspetto RAG Tradizionale RAG Agentica
Retrieval Single-shot, statico Multi-step, dinamico
Query Query originale dell'utente Query riformulate dall'agente
Valutazione Nessuna L'agente valuta i risultati
Iterazione No Sì, fino a soddisfazione
Tool use Solo vector search Multiple fonti e strumenti

Capacità della RAG agentica

Query decomposition

Scompone domande complesse in sotto-query più semplici da risolvere separatamente.

Routing intelligente

Decide quale fonte interrogare in base al tipo di domanda.

Self-reflection

Valuta la qualità dei risultati e decide se cercare ancora o rispondere.

Multi-hop reasoning

Usa informazioni da una ricerca per formulare la successiva.

Esempio: RAG agentica in azione

Query: "Confronta le performance Q3 2024 di Apple e Microsoft"

1

Planning

"Devo cercare i report Q3 di entrambe le aziende separatamente."

2

Retrieval 1

Cerca "Apple Q3 2024 earnings" → trova revenue, profit, guidance.

3

Retrieval 2

Cerca "Microsoft Q3 2024 earnings" → trova metriche equivalenti.

4

Synthesis

Combina i dati, crea confronto strutturato, cita le fonti.

Best practices

1. Inizia semplice

RAG base prima di passare ad agentic. Valida che il retrieval funzioni.

2. Qualità dei dati

Garbage in, garbage out. Cura la pulizia e struttura dei documenti.

3. Evaluation

Misura retrieval precision/recall. Usa framework come RAGAS.

4. Guardrails

Limita iterazioni degli agenti. Implementa timeout e fallback.
