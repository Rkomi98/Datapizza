03 · Session 01 · 3h

Understanding & engineering coding agents

Why this matters

Coding agents can navigate large repositories, modify code and execute commands. Their usefulness depends heavily on the information and tools they receive.

For a team working across Python, MATLAB, C++ and numerical applications, incomplete context can lead to incorrect assumptions, unnecessary changes or results that are hard to reproduce.

Topics
How LLMs work in two minutes Agent capabilities & limitations Context engineering Project instructions Skills Tools Introductory MCP concepts Intro to harness engineering
Hands-on · 2 slots × ~30 minPick one option per slot

Context engineering

Explore an unfamiliar engineering repository and identify the files, dependencies and constraints needed for a task.

Improve project instructions and compare the agent's behaviour before and after.

Reusable Skills

Create a Skill that standardises a recurring engineering procedure.

Debug and improve an existing Skill, measuring whether the agent follows it correctly.

Outcome

Participants understand how to make coding agents work consistently within an engineering project.

04 · Session 02 · 3h

The agentic software lifecycle

Why this matters

As coding agents take on more implementation work, engineers increasingly need to focus on problem definition, architecture, verification and accountability.

This matters particularly in numerical engineering: code that executes successfully can still produce physically or mathematically incorrect results.

Topics
Agentic planning Implementation Debugging Testing Controlled refactoring Subagents Hooks Permissions Review Evaluation Resource efficiency
Hands-on · 2 slots × ~30 minPick one option per slot

Reliable development

Detect a hidden numerical defect using independent reference tests.

Refactor an existing engineering module while preserving its expected behaviour.

Controlled autonomy

Configure Hooks and guardrails to verify or restrict agent actions.

Delegate a specialised code review to a Subagent and evaluate the usefulness of its findings.

Outcome

Participants learn to supervise an agentic development workflow and assess its output through reproducible evidence.

The four slots give a common learning progression. We select the alternatives together and adapt their technical context to Audi's priorities.
